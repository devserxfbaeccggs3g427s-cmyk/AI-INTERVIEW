1. Ẩn dụ trực quan: “Chiếc thẻ từ độc quyền phòng khách sạn”

Mental Model
groups 5 Microservices (Nhân viên)

5 nhân viên dọn phòng cùng nhận lệnh dọn phòng VIP số 101. Nếu không có cơ chế điều phối chung, cả 5 người sẽ ùa vào cùng lúc gây xáo trộn đồ đạc (Race Condition).

credit_card Thẻ từ duy nhất tại Bàn lễ tân (Redis)

Lễ tân chỉ giữ đúng 1 thẻ từ duy nhất (NX). Ai chạy đến lễ tân trước được cầm thẻ vào dọn. 4 người đến sau bị từ chối ngay lập tức và phải chờ.

timer Thẻ tự bốc cháy sau 30 giây (TTL)

Nếu nhân viên đang dọn phòng mà ngất xỉu (Worker crash), sau đúng 30s (PX 30000) thẻ tự hủy và tạo ra thẻ mới tại quầy, tránh phòng bị khóa vĩnh viễn (Deadlock).

2. Nguyên lý hoạt động từng bước (Step-by-Step)

Architecture Primitives
1 Vì sao `Mutex` hay `synchronized` trong Java / Node.js thất bại khi lên Cloud?

Các biến cờ trong RAM chỉ có tác dụng trong 1 Process (tiến trình) của 1 máy chủ duy nhất. Khi bạn chạy Kubernetes với 5 Pod hoặc nhiều Server độc lập, RAM của Server A hoàn toàn không chia sẻ được với RAM của Server B. Do đó, bắt buộc phải có một bên thứ ba tập trung có tốc độ truy xuất cực nhanh – đó chính là Redis.

2 Bản chất câu lệnh chuẩn nguyên tử: `SET resource_key my_unique_token NX PX 30000`
• NX (Not eXists): Chỉ gán key nếu key chưa hề tồn tại trong Redis. Nếu đã có người giữ lock, câu lệnh trả về nil (thất bại).
• PX 30000: Khóa tự động hết hiệu lực sau đúng 30,000 milliseconds (30 giây) để phòng chống sự cố chết luồng (Crash-safety).
• my_unique_token: Phải là một chuỗi ngẫu nhiên duy nhất (UUID v4), tuyệt đối không dùng số tĩnh như '1' hay 'true'.
3 Giải phóng khóa an toàn bằng Lua Script: Chống xóa nhầm lock của đồng nghiệp

Giả sử Server A bị lag vượt quá 30s khiến lock hết hạn. Server B liền vào lấy lock mới. Lúc này Server A tỉnh lại, nếu A chạy lệnh `DEL resource_key` thì A sẽ vô tình xóa mất lock của Server B! Do đó, việc xóa lock bắt buộc phải dùng Lua Script để kiểm tra xem giá trị hiện tại có đúng bằng my_unique_token của mình hay không rồi mới được xóa.

3. Code mẫu thực tế (TypeScript / Node.js)

Production Safe Template
redis_distributed_lock.tsNode.js + ioredis
// 1. Giành khóa nguyên tử với UUID ngẫu nhiên và TTL 30 giây
const lockKey = "lock:order:10293";
const lockToken = crypto.randomUUID(); // Bắt buộc sinh token duy nhất
const ttlMs = 30000; // 30s phòng chống Deadlock

const acquired = await redis.set(lockKey, lockToken, "NX", "PX", ttlMs);
if (!acquired) {
  // Có tiến trình khác đang xử lý đơn hàng này
  throw new Error("Tài nguyên đang bận, xin vui lòng thử lại sau!");
}

try {
  // 2. Thực thi xử lý critical section (trừ tiền ví, cập nhật kho...)
  await processPaymentAndInventory();
} finally {
  // 3. Giải phóng lock an toàn bằng Lua Script (Chỉ xóa nếu đúng token của mình)
  const releaseLuaScript = `
    if redis.call("get", KEYS[1]) == ARGV[1] then
      return redis.call("del", KEYS[1])
    else
      return 0
    end
  `;
  await redis.eval(releaseLuaScript, 1, lockKey, lockToken);
}
